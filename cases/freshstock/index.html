01 / Overview

An asset library built for use, not just browsing.

FreshStock brings curated graphic assets from Design Pickle into a searchable subscription experience. Members can download editable source files, organize assets in Collections, and revisit their download history.

The product connects three moments in a creative workflow: discover a useful asset, get the source files, and keep the work organized.

The supplied screens show themes and asset types as entry points, a detailed asset view with save and download actions, personal Collections, and a month-based Downloads history.

03 / Framing

One library, three kinds of continuity.

The design question is how to move from inspiration to a usable file while preserving enough context to resume the work later.

Across discovery

The home screen offers several paths into a large catalog. Themes, asset types, new work, and search each serve a different starting point. The asset detail page has to make the next action clear without flattening that variety.

Across sessions

A downloaded asset and a saved asset represent different intentions. History answers “what did I use?”; Collections answer “what might I use?” Both need a reliable route back to the source.

A useful job story for evaluating the journey: “When I find a promising graphic, I want to inspect it, get the right editable file, and save it in a project context so I can keep moving.”
Analytical framing based on the supplied product screens; this is not a quote from user research.
04 / User flow

Two intentions, one asset detail.

Both paths begin with discovery and converge on the asset detail screen. From there the user either gets a file now or organizes the asset for later.

Primary path: discovery → asset detail → authentication if needed → file choice → download → history.

Secondary path: discovery → asset detail → save → choose an existing Collection or create one → confirmation → return through Collections.

05 / Interface logic

Make the next action visible at every stage.

These editorial recreations abstract the supplied UI into three decisions. They are explanatory visuals, not new shipped screens.

Asset detail

Place file access next to context.

The preview and available file types help a subscriber decide whether the asset is useful before the download action.

Collections

Continuity

Keep “save” distinct from “download.”

Collections support prospective work; Downloads history supports retrieval of files already used. Both retain a path back to the asset.

Design tradeoff to validate: the asset detail shows Save to collection, Download, and Start new request with asset in close proximity. A usability test should check whether subscribers understand the difference between these actions, especially on a narrow screen.
